# Keep books across a server restart

**Status:** Done
**Left to do:** nothing
**Branch / PR:** `api/persist` · PR link in the pull request
**Builds on:** decisions log 2026-10-07 (PATCH id handling); the owner's task brief of 2026-10-07

## Goal
Books added or marked read are still there after the server restarts. They live in a JSON file,
`data/books.json` by default, or wherever `BOOKS_FILE` points.

## Out of scope
- Concurrent writers (two servers on one file), file locking, a database.
- Migrating or validating each book's fields in an existing file (backlog: `books-file-bad-ids`).

## Open questions
All settled by the owner on 2026-10-07 (decisions log, "How the books file is created, located,
guarded and kept out of git"):
- **Unreadable or invalid file** (bad JSON, not an array, can't be read): the server refuses to
  start, names the file and leaves it untouched.
- **When the seed is written:** at startup, as soon as the file is found missing.
- **`data/` should be gitignored.** The root `.gitignore` is outside every lane and the lane check
  refused the commit, so the owner dropped that change from this task and will add the line
  (`data/`) themselves.
- **Relative `BOOKS_FILE`** resolves against the project root, like the default.

## Reuse
- `server/app.js`: routes unchanged; the in-memory array is now loaded from and saved to the file.
- `server/app.test.js`: `withServer` helper, extended to give each server its own temp file.
